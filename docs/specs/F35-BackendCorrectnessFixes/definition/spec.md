# F35 — Backend Correctness & Security Fixes

**Kind:** technical (tech-spec — the architect owns the definition)
**Source:** F34 audit — `docs/specs/F34-ConventionsAudit/delivery/audit-report.md` § 1; finding rows in `docs/specs/F34-ConventionsAudit/delivery/findings/backend.md` (BE-*) and `findings/skills.md` (SK-*)
**Dependencies:** F33 (done), F37 (packages settle first — same backend lane)
**Rule list:** not applicable — defect fixes against existing behaviour; the rules they restore are stated below
**Review:** round 1 — `delivery/review-critic.md`
**Status:** Ready
**Plan:** docs/specs/F35-BackendCorrectnessFixes/delivery/plan.md

## Purpose

The backend has real defects a student cloning the repo would hit or copy: domain events can be lost or published before their data is committed, other participants' card text leaks during the Writing phase, rule violations come back as 500s with raw exception text, a closed sprint can still be edited, and kicking an active participant crashes. This feature fixes those defects and the security holes the audit found. It does not restructure the code — that is F38, which builds on what this feature leaves.

## Scope

Each row's "suggested fix" in the findings file is the required outcome, unless the "Required outcome" column below narrows it or picks between its options.

| Finding(s) | Defect | Required outcome |
|---|---|---|
| BE-01, SK-01 | The event interceptor is a singleton holding per-save state | Registered scoped and resolved from the context's provider; a failed save, or a rolled-back transaction, discards its pending events. |
| BE-12, SK-14 | Multi-step changes are saved in several non-transactional saves, and events go out after the first save | **The interceptor becomes transaction-aware:** while an explicit transaction is open, events collected by its saves are held and published only after the commit, and dropped on rollback; with no transaction, events publish after the save as today. `AdvancePhase` (leaving Writing), `CreateGroup`, `DissolveGroup` (no save per card in a loop) and `RemoveCardFromGroup` each run in one explicit transaction. The SignalR messages these endpoints still send inline today (`CreateGroup`, `DissolveGroup`) are sent only after the commit, and not at all on rollback. A client that refetches on `PhaseChanged`, `GroupCreated` or `GroupDissolved` therefore always reads committed data with the cards in their groups. F38 relies on this mechanism and does not build it again. |
| BE-02 + the read paths the review found | Writing-phase card content reaches other participants | **One redaction rule**, used by every path that returns card content during Writing: `ListCards`, `GetGroups`, both report endpoints (`GetSprintReport`, `GetParticipantReport`), and every card broadcast (card created, edited, evidence attached, detached). **Who sees what during Writing:** the rule applies only to cards of the sprint that is in Writing — previous-action cards from the closed previous sprint (`GetPreviousActions`, the reports' previous-actions section) are shown as today. For those current-sprint cards, a request or connection carrying a participant identity sees the full content of its own cards only; every other card is redacted to the shape `ListCards` returns today (text empty, no assignee, no evidence links), and any value derived from a redacted card — the report's group title, taken from its first card's text — is redacted with it. A request with no participant identity (the team owner signed in with Google only, no guest token) sees full content — today's REST behaviour, unchanged. The `EvidenceLinkFetched` notification is sent during Writing only to the card author's connections. Delivery to the author goes through a per-participant SignalR group joined in `JoinSprint`. |
| BE-07, SK-04, SK-05 | Domain rule violations surface as 500 | State-rule violations in `Sprint` and `Card` throw `DomainException` (it exists in `Blocks.Domain`) instead of `InvalidOperationException`; the middleware maps `DomainException` to 409 (today 400, never thrown). `ArgumentException` stays for bad arguments → 400. Defensive arms that only a programming error can reach keep `InvalidOperationException` and stay 500: `Sprint.cs` "no timer default for phase" and "unknown phase", `Card.cs` "EvidenceLink not found" ×2. `SetReviewStatus` on a card that is not an action item returns 404. The unit-test assertions on the converted throws are updated: `tests/Reflekt.UnitTests/Sprints/SprintTests.cs` (lines 83, 93, 134, 142, 188, 198 at review time) and any `EvidenceLinkTests` assertion on a converted throw. |
| BE-20, SK-07 | Raw exception text returned for 5xx | Outside Development a 5xx body carries a generic message and the trace id only, no `Details`; the real exception is logged (already is). Status taken from `HttpException.StatusCode`. The middleware's body is serialised camelCase — **F35 sets this key casing; F38 keeps it and adds `code`.** |
| BE-14 | A closed sprint can still be grouped, renamed and re-columned | `Sprint.EnsureOpen()` throws `DomainException("Sprint is closed.")` → 409. It guards the five card-group endpoints (`CreateGroup`, `AddCardToGroup`, `RemoveCardFromGroup`, `DissolveGroup`, `UpdateGroupTitle`), `UpdateColumns`, the hub's timer methods, and the timer auto-start in the hub's `JoinSprint` (a closed sprint never starts a timer). It runs after the 404/403 checks and before the phase-action check. Endpoints that already reject a closed or non-active sprint keep their current message and status. `SetReviewStatus` guards the sprint doing the review, never the closed previous sprint whose action item it updates. |
| BE-13, SK-17 | Kicking a participant who wrote a card or voted fails on a restrict foreign key | **Soft kick (owner decision 2026-10-22).** `Participant` gets a removed marker; `Kick()` sets it and raises the existing event; the kick endpoint keeps its 204. Kicking an already removed participant is a no-op 204. A removed participant's guest token fails authentication (401). Every hub method (`JoinSprint`, `ToggleReady`, the timer methods) rejects a removed participant, so an open connection cannot rejoin. One ordered handler on the kick event: broadcast `ParticipantKicked` to the sprint group (the SPA navigates away on it), then remove that participant's connections from the sprint and participant groups and abort them, then drop them from readiness and connection state and broadcast the updated readiness. **The revocation runs even when a broadcast fails or is cancelled** (eviction, abort and state cleanup are not skipped by an exception in the sends). Cards and votes stay. Removed participants are left out of `ParticipantRepository.GetBySprintIdAsync` (participant lists, the anonymous summary, reports, the advance-phase check's voter count) and of the display-name uniqueness check; `GetByUserAndSprintAsync` still returns them, so a removed Google participant rejoining the same sprint gets 409. A guest can join again only as a new participant. |
| BE-15, SK-23 (display-name part) | "Display name unique per sprint" is enforced only by read-then-insert | A unique index on participants `(SprintId, DisplayName)`, case-insensitive, filtered to participants not removed; a violation returns 409. The migration first renames existing active duplicates (see Decisions). "One vote per group" gets **no** index: `CastVote` already runs in a serializable transaction; the dev seed's double vote by one participant on one group is removed. The team-count race (SK-23's other half) is not fixed here: it is recorded as a known deviation in F40. |
| BE-19, SK-11 (part) | Out-of-range enum values persisted; null `CardIds` crashes `CreateGroup` | `ColumnType`, `CardType` and review status are rejected (400) unless they name a defined value (numeric strings rejected; `ReviewStatus.None` stays rejected); `CreateGroup` validates `CardIds` not empty and distinct and keeps its "at least 2 cards" rule; `UpdateGroupTitle` validates length ≤ 100. One validation per input — the second inline parse is removed. |
| SK-09 (part) | `GetUserId()` throws `InvalidOperationException` (→ 500) when the claim is missing | Throws `UnauthorizedException` → 401. |
| BE-21 | Open redirect after sign-in | A return URL is used only when it starts with exactly one `/`, the next character is neither `/` nor `\`, it contains no control character (below U+0020, or U+007F) and no `://`; otherwise the login falls back to `/` (no error). `/sprint/12` — what `RetroJoinForm.vue` sends — is accepted. The rule is one public static function in the login slice. The dev front-end origin comes from configuration, not a literal in the endpoint. |
| BE-23 | SSRF guard misses IPv6, mapped addresses, 0.0.0.0, 100.64/10; redirects and DNS rebinding unchecked | Every address the fetcher connects to is checked at connect time (`SocketsHttpHandler.ConnectCallback`), rejecting loopback, private, link-local, unique-local, CGNAT, unspecified, multicast and broadcast ranges in IPv4 and IPv6 and IPv4-mapped IPv6; automatic redirects are off, or each hop goes through the same check. The address check is one public static function. |
| BE-28 (part) | The guest token is accepted from the `access_token` query string on every route | The query-string token is accepted only on `/hubs/*`; header and bearer forms are unchanged. |

## Decisions (taken — owner or architect)

| Decision | Why | Rejected alternative | Confidence |
|---|---|---|---|
| **Soft kick** (owner, 2026-10-22), as specified in the BE-13 row. | Keeps the team's retro content; matches "retire by marking, never delete". | Delete their votes and cards; refuse the kick while they have content. | high — owner's pick |
| F35 owns transaction-aware event publication; F38 only uses it. | Both readers found the "after commit" outcome had no mechanism in F35 and a duplicate in F38. | Reorder saves per endpoint; leave it to F38. | high |
| No vote unique index; the display-name index repairs data by renaming. The migration keeps the lowest-id participant's name and gives each later active duplicate (compared case-insensitively) the first free suffix ` 2`, ` 3`, …, trimming the base so the result stays within 50 characters and is free against every active name in that sprint. No row is deleted. | Deleting duplicate votes would rewrite past sprint reports on a live database; `CastVote`'s serializable transaction already prevents new duplicates. | Vote index with deletion of duplicates. | medium — renames users' display names on an existing database |
| Redaction follows today's REST rule for every path (participant identity → own cards only; no participant identity → full), so the owner's live view is the same as their REST view. | One rule; the review showed "owner unchanged" was undefined on SignalR, where every connection is a participant. | Exempt an owner who is also a participant. | high |
| Tests: no new test project, framework or helper library. A fix that changes behaviour gets its regression case in the existing test class for that area; where no class covers the area (return-URL rule, SSRF address check, redaction rule) a new test class goes into the existing unit-test project. | Owner's rule — no tests "unless we have them already" — read as: the existing projects and tools only. An untested security fix is not a fix. | No new test cases at all. | medium — reading of the owner's rule |
| SignalR delivery is tested at the handler level with handwritten fakes of the hub context (recipients and payloads captured), not end to end with a SignalR client. | Proves recipients and payloads without a new package. | Add `Microsoft.AspNetCore.SignalR.Client` to the tests. | high |

## Out of scope

- Every conventions/structure finding not named above — F38 (BE-03…06, BE-08…11, BE-16…18, BE-22 (F37), BE-24…38 except the BE-28 part above, SK-02, SK-03, SK-06, SK-08, SK-10, SK-12, SK-13, SK-15, SK-16, SK-18…SK-22, SK-24…SK-30).
- The team-count race (SK-23's other half) — a known deviation, F40.
- The login allowlist: **not** enforced in code (owner, 2026-10-13); the docs are corrected in F40.
- Frontend changes: none needed — the SPA reads no middleware error body field, and it already leaves the room on `ParticipantKicked`.

## What must not change

- Routes, request and response field names, and every status code except: domain-rule violations that were 500 become 409; `SetReviewStatus` on a non-action-item becomes 404; invalid enum, group and title input becomes 400; a missing user claim becomes 401; a closed sprint on the guarded endpoints becomes 409; a removed participant's token becomes 401.
- Writing-phase behaviour for the author, and today's REST behaviour for the owner.
- The previous-action review of a closed sprint's action items keeps working.
- Existing tests keep passing; a test that asserted a defect or a converted exception type is updated and named in `implementation.md`.
- No package version changes (F37 owns them).

## Acceptance (checkable)

1. `grep -rn "AddSingleton<DomainEventPublishingInterceptor>" src` → no hits. Tests in existing classes show: a failed save publishes nothing; a rolled-back transaction publishes nothing; two concurrent scopes never publish each other's events; after leaving Writing, every note is in a group when `PhaseChanged` goes out; `CreateGroup` and `DissolveGroup` send nothing when their transaction rolls back.
2. `grep -rn "InvalidOperationException" src/Services/Reflekt/Reflekt.Domain` → only the four defensive arms named in the BE-07 row.
3. Integration tests in existing classes: a closed sprint → 409 `Sprint is closed.` on `CreateGroup` (in a phase that allows grouping) and on `UpdateColumns`, with data unchanged — this also proves the `DomainException` → 409 mapping; `SetReviewStatus` on a note card → 404, and on an action item of the closed previous sprint still succeeds; a 5xx body has no `message` text from the exception and no `details` outside Development.
4. Kick, in `ParticipantEndpointTests`: kicking a participant with a card and a vote → 204; the card is still listed; their token → 401; a removed Google participant rejoining → 409; a second kick → 204. A handler test with a hub fake whose send throws shows eviction, abort and state cleanup still happen.
5. Redaction: unit tests of the rule (own card full; other card redacted; no participant identity full; previous-sprint card untouched; a group title derived from a redacted card redacted). Integration: in Writing, `ListCards`, `GetGroups` and both report endpoints return no text, assignee or evidence of another participant's current-sprint card anywhere in the body, and still return the previous actions. Handler tests with hub-context fakes, for card created, edited, evidence attached, detached and fetched: the author's connections (two of them) receive the full payload, other participants receive the redacted one (fetched: nothing), and no full payload goes to the sprint group.
6. Return URL: unit tests accept `/sprint/12` and reject `//evil.com`, `/\evil.com`, `/` + tab + `/evil.com`, and `https://evil.com`.
7. SSRF: unit tests of the address check cover each listed range in IPv4 and IPv6, an IPv4-mapped address, and one public address allowed; a fetch of a local test server on `127.0.0.1` fails at connect.
8. Integration tests: `?access_token=` on a non-hub API route → 401, while the header and bearer forms still authenticate and the hub's negotiate request with `access_token` still succeeds; a request authenticated without a user id claim → 401; a numeric `ColumnType` → 400 and nothing saved; `CreateGroup` with null or one card → 400.
9. A new migration adds the removed marker and the filtered unique index; the integration suite starts clean (the API's start-up `Migrate()` throws on a pending model change). One run of the migration over a copy of a database holding duplicate active names in a sprint (`Ana`, `ana`, `Ana 2`, two identical 50-character names) is recorded in `implementation.md` with the names after; inserting a duplicate active name afterwards → 409.
10. The declared full role in `.claude/verify.json` passes.
