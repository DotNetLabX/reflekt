# F36-FrontendDefects — Lessons

## Architect Lessons

- **A store-level "clear on fetch start" rule must be checked against every caller of that fetch, not only the views.** The F36 tech-spec (FE-08) says every fetch clears its target data when it starts; `cardGroup.fetchGroups` and `card.fetchCards` are also re-run by SignalR hub handlers (`useSprintHub.ts:67-71,108-120`) and after every group mutation (`cardGroup.ts:64,79,92,105,158`), so a literal clear would blank the board on every group change. The plan applies the rule per target (clear when the fetch is for a different sprint/team than the data held). When writing a state contract for a store, grep the fetch's callers (`grep -rn "\.fetchX("`) before fixing the wording.
- **A manual-walkthrough acceptance cannot be discharged by an "operator-owed, Deviated (valid reason)" fallback.** The F36 round-1 plan let unobserved AC6 items pass the done check as a justified deviation; the plan critic (R1-05, HIGH) rejected it because the spec asks for an observation per item. The fold that held: a separate `Owner: operator` step, with the acceptance kept open until it is recorded and the close reporting it as open. Use this shape for any acceptance that needs a human (OAuth sign-in, hearing audio), not the build-time-unavailable-resource fallback.
- **A "never another target's data" guarantee in a Vue SPA has to cover component reuse on a route-param change.** F36's views read their ids once at setup and load on mount, and `App.vue`'s `<RouterView>` is unkeyed, so Vue Router reuses the instance between `/sprints/5` and `/sprints/7` and no load runs; request counters cannot guard a request that never starts (plan review R2-02, missed in round 1). When planning load/stale-data contracts, check how each view reacts to its own route params (`watch` or a keyed `RouterView`) before relying on store-level guards.
- **Done check (F36):** a build session can drive a real browser over CDP (headless Chrome + Node's built-in WebSocket, no package added) and inject offline/500 per request with `Fetch.failRequest` / `Fetch.fulfillRequest` — enough to observe every guest-reachable walkthrough item. What it cannot reach is anything behind Google OAuth, Scrum-Master-only phase moves, a second client's hub event, or hearing audio. A plan with a manual-walkthrough acceptance should split its items up front into "observable by a headless guest session" and "operator-owned", so the operator step is sized at plan time rather than discovered at Step 13.
- **An ownership argument based on ordering ("a later call always stops the previous one first") does not hold when two callers can await the same step at once.** My F36 Q1 ruling said a resolved `connect()` meant the shared hub connection was the caller's own. Codex then reproduced two room entries waiting on the same teardown inside `connect()`, both building, and the stale one's `disconnect()` stopping the live room's hub. The Q2 fix that holds: one module-level promise-chain lock around every lifecycle call (connect and disconnect), plus a per-instance `ownedConnection` checked against the shared one before stopping. Before ruling on shared-singleton lifecycle, list every place that can be awaiting concurrently, not just the order of the calls.
- **A lock around network lifecycle calls also needs cancellation, or a call that never settles holds it forever.** The F36 Q2 lock serialized hub `connect`/`disconnect`, but teardown then queued behind a `JoinSprint` `invoke` that has no timeout, so a room left mid-join stayed connected and blocked the next room (cycle 3 HIGH, escalated after the cap). The Q3 shape: capture the connection object synchronously before the first `await`, and on leave stop that object directly, outside the queue, so the locked operation rejects and releases. When ruling on exclusion around I/O, also say how the holder is cancelled.
- **Escalation rulings on a third-party lifecycle must be checked against the installed package before they are written, not after they fail review.** On F36, three rulings in a row (questions.md Q1–Q3) on the SignalR hub teardown each failed Codex re-review. Each one rested on an unchecked claim about how `@microsoft/signalr` behaves: that a later `connect()` always stops the previous connection first, and that `stop()` rejects a pending start at once. Reading `node_modules/@microsoft/signalr/dist/esm/HttpConnection.js` (Q4) showed that `stop()` waits on a held WebSocket opening and that the private module `connection` cannot be released from outside. That made a fix without amending the pin impossible, which a 10-minute read would have shown at Q3. Rule: when a ruling depends on library timing, read the installed source and cite `file:line` in the ruling. A confidence label above medium is not allowed until that is done.
- **Before ruling continue-or-abort on an escalated HIGH, check whether `main` already has the defect.** `git show main:{file}` showed the held-socket block predates F36. That turned a "fix it or ship a regression" question into "defer a pre-existing defect", and that is what decided the abort.
- **Repeated fix rounds on a concurrency defect that each add machinery (a counter, then a lock, then cancellation) mean the model is wrong.** The class closes by removing the waiting: synchronous ownership by object identity, with nothing awaiting another connection's lifecycle. It does not close by adding another guard.

## Developer Lessons

- **On this Windows checkout (`core.autocrlf=true`, CRLF working tree), Git Bash `sed -i` rewrites every file it touches to LF.** The index diff stays clean, so `git diff` hides it, but the working tree turns LF-only (`git ls-files --eol` shows `w/lf`) and git warns "LF will be replaced by CRLF" for each file. For a bulk regex edit, follow with `perl -pi -e 'binmode STDIN; binmode STDOUT; s/\r?\n/\r\n/'` on the touched files, or use `perl -pi` for the edit itself; check with `git ls-files --eol`. The Edit tool keeps CRLF.
- **A Vue `inheritAttrs: false` split reads `useAttrs()` from the render, never through `computed()`.** `attrs` is not reactive, so a computed caches the first attributes; a plain function called in the template stays current (F36 Step 3, `BaseInput.vue`).
- **"Latest request wins" through a request counter breaks an action that several callers await and then read state from.** The caller whose request was superseded resumes after its `await` before the newer request has saved anything, so it reads state that is still empty. In F36 that was `auth.fetchMe`, called by both the router guard and `App.vue` on a cold load. A counter would have sent a signed-in user away from a guarded route. Concurrent callers share one in-flight promise instead. Before adding a counter, check each caller for `await action(); read state` (F36 Step 4).
- **The Write tool writes LF.** On this CRLF checkout, after a whole-file `Write`, re-save the file with CRLF line endings (a `node` one-liner replacing `\r?\n` with `\r\n`) and check with `git ls-files --eol`.
- **A recorded UI walkthrough can run unattended in this repo with nothing new installed.** Run the API with the built SPA on a scratch database (`ConnectionStrings__Reflekt="Data Source=<repo>/.claude/tmp/…/reflekt.db"`, `Seed__Enabled=true`, `dotnet run --no-launch-profile --urls http://localhost:<free port>`). The seed gives an Active sprint 1 in Writing that a guest can join at `/sprint/1`. Drive the installed Chrome headless over the DevTools protocol from a Node script: Node 24 has a global `WebSocket`, and `PUT /json/new` gives a page target. Inject failures with CDP `Fetch` (`failRequest` with `InternetDisconnected` for offline, `fulfillRequest` with 500), and read the screenshots back as images. It reaches guest flows only: sign-in is Google OAuth, and phase moves need the Scrum Master. Stop the API through its port's process afterwards, because stopping `dotnet run` leaves `Reflekt.API.exe` listening (F36 Step 13).
- **Tailwind v4 changed the default border colour to `currentColor`.** A bare `border`, `border-t` or `border-b` with no colour class renders as a black rule in the light theme (`RetroColumnPanel.vue:9`, `:67`). Grep for border utilities without a colour when auditing v3 → v4 drift (F36 Step 13; carried over for F39).
- **Store request counters don't protect a multi-await flow in a view or composable.** When the old view's flow resumes after unmount, it starts new requests, so its own requests are now the newest and the counters let them through. It also reads store state the next view has loaded (the next sprint's `currentSprint`). Every async entry flow that crosses awaits needs its own number, raised on unmount and on a new run, and checked after each await before it writes shared stores, the guest token or the module-wide hub. Codex caught this in `useRetroRoom` and `SprintView` (F36 fix round 1).
- **Clearing a store list when its load starts breaks components that read the list in `onMounted`.** A child mounts while the parent's load is in flight, so it reads an empty list. `CreateSprintForm`'s pre-fill from the latest sprint stopped working that way. Before clearing on start, grep for readers of the list and move any one-shot read to a watch on the load ending (F36 fix round 1).
- **A caller-side cancellation check after `await store.action()` can't stop a write that the action makes itself.** `participantStore.join` / `joinWithGoogle` set `currentParticipant` before they returned, so the composable's check after the await came too late (Codex, F36 fix cycle 2). When several actions write the same shared field, guard that write inside the store with one generation number the actions share. Add an action that raises the number, for the caller to use when it gives up (`abandonPendingIdentity()` on unmount).
- **In Git Bash, `grep -c $'\r$'` is not a check for CRLF.** It counted every line of a file that `sed -i` had just turned to LF (this restates the `sed -i` entry above for F36 fix cycle 2). Check line endings only with `git ls-files --eol`.
- **A pre-fill that lands after an editable form is shown must leave alone any field the user already changed.** Record edits per field (`@input`, or the picker's `@click`) and fill only the untouched fields. Disabling the form while it loads adds a state the form never had (F36 fix cycle 2, `CreateSprintForm`).
- **When several component instances share one module-level async resource (here the SignalR hub in `useSprintHub.ts`), "who owns it" cannot be argued from call order.** Two callers that await the same teardown inside `connect()` both pass it and both build, so a later bare `disconnect()` can stop the other instance's connection (F36 fix cycles 1-2 both shipped an ordering argument, and Codex broke each). The fix that held: one module-level promise-chain lock (`withHubLock`) around every connect/disconnect, a per-instance owned handle compared by identity before stopping, and a supersession check on acquiring the lock (F36 fix cycle 3, `useRetroRoom.ts`).
- **A lock that wraps a network call with no time limit must also be cancellable, or teardown can wait forever.** Q2's `withHubLock` made `connect()` exclusive, but `invoke('JoinSprint')` can hang. An unmount queued behind it never ran (Codex, F36 fix cycle 3). The fix: start the call without awaiting it, and capture its resource on the very next line, before any `await`. A leaving instance then stops that resource directly, outside the lock. The locked op settles and does its cleanup inside the lock. Recheck supersession after every `await` inside the locked op that comes before the cancellable call. Otherwise a leave during that `await` finds nothing in flight to cancel (F36 fix cycle 4, `useRetroRoom.ts` `cancelHub`).
