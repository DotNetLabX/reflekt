# Open Actions from Previous Retro — Guide

## Actions from last sprint section
At the start of each retro, you'll see action items from your team's most recent completed retro. This section helps you review what was committed last time before generating new discussion. The Scrum Master marks each item, while participants can see the statuses but not change them. You can continue writing notes in the columns below while the review happens -- both activities run in parallel.

## Done button
Use this when the action item has been completed since the last retro. The team delivered on the commitment and no further action is needed. If you change your mind, click a different status button to switch.

## Carried Over button
Use this when the action item is still relevant but hasn't been completed yet. This signals to the team that the commitment carries forward. If you want to track it in the current retro, create a new action item during the Discussing phase with updated context. The original item stays in the previous sprint's record for traceability.

## Dropped button
Use this when the action item is no longer relevant -- priorities changed, the problem resolved itself, or the team decided it's not worth pursuing. Dropping an item is a deliberate decision, not neglect. It keeps the action list honest by removing stale commitments.

## Review summary line
Once every action item has a status, the section collapses to save space. The summary shows the breakdown (e.g., "3 done, 1 carried over, 1 dropped"). You can expand the section at any time during the Writing phase to revisit or change a status.

## Advance warning (unreviewed items)
If you advance to the next phase without reviewing all action items, a confirmation dialog shows how many items are still unreviewed. Reviewing previous actions is a best practice -- skipping it is a common retrospective anti-pattern. However, the advance is not blocked; you can proceed if the team has already discussed the items verbally or if the previous actions aren't relevant.
