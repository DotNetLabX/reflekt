# Known Deviations

Recurring implementation mistakes tracked across features. Developer reads during Phase 1 pre-flight. Learner populates from lessons.md analysis.

A second table, **Accepted deviations**, lists the deliberate departures of the code from a project skill or rule: what differs, why it stays, and where. Read it before "fixing" code back to a skill.

## Accepted deviations

| What | Why | Where |
|------|-----|-------|
| **Event-handler failures are logged, not rethrown.** `domain-patterns` shows the publisher awaiting `PublishAsync(Mode.WaitForAll)`, so a handler exception would reach the caller; here publication is awaited the same way, but each failure (or cancellation) is logged with `LogError` and the save, the commit and the request still succeed. | The data is already committed when handlers run; a failed broadcast must not turn a saved change into an error response (F38 Fix Round 1, plan P7). | `src/BuildingBlocks/Blocks.Persistence/DomainEventPublishingInterceptor.cs` (`PublishInOrderAsync`, `LogFailures`); `docs/architecture/architecture.md` § 3 |
| **An evidence-link attach waits while the OpenGraph queue is full.** The fetch queue is `Channel.CreateBounded<FetchJob>(100)` with `FullMode = Wait`, and the attach handler writes to it inside the awaited publication, so with 100 jobs queued the attach request waits for a free slot. | Follows from awaiting publication (row above); F38's accepted residual (Fix Round 1, P7). | `Reflekt.API/OpenGraph/OpenGraphConfiguration.cs`; `Features/EvidenceLinks/AttachEvidenceLink/BroadcastAndFetchOnEvidenceLinkAttachedHandler.cs`; `architecture.md` § 5 |
| **Hub state lives in one process.** Timers, readiness, the connection registry and the fetch queue are in-memory singletons, and there is no SignalR backplane: the app must run as a single instance. | The app is deployed as one Azure App Service instance; a backplane or a shared store would be new infrastructure. | `Reflekt.API/Hubs/TimerService.cs`, `Hubs/ReadinessTracker.cs`, `OpenGraph/`; `architecture.md` §§ 8, 13 |
| **Two URL schemes.** Team-scoped `/api/teams/{teamId}/sprints…` (the scrum master's sprint management, 9 routes) beside sprint-scoped `/api/sprints/{sprintId}/…` (the retro room, 27 routes); `POST …/advance-phase/check` is a read. | Documented rather than unified (BE-36): changing routes changes the API the SPA calls, which is out of scope for a conventions cleanup. | `Reflekt.API/Features/**/*Endpoint.cs` route attributes; `architecture.md` § 4 |
| **Team-count race.** `TeamLimitCheck` counts the owner's teams, then the endpoint inserts; two concurrent creates can both pass `TeamSettings:MaxTeamsPerUser`. | A database-level limit would be new behaviour (campaign rule: no new product behaviour); the window is two simultaneous requests by the same user (SK-23). | `Features/Teams/CreateTeam/TeamLimitCheck.cs`, `CreateTeamEndpoint.cs` |
| **Team-name duplicates: the check ignores case, the index does not.** `TeamRepository.ExistsByOwnerAndNameAsync` compares names with `NOCASE`, so a sequential `alpha` after `Alpha` is refused (`duplicate_name`, 409); the unique index `IX_Teams_OwnerId_Name` compares `Name` in SQLite's default binary collation (`Teams.Name` has no `NOCASE`), so it stops only an exact duplicate. Two concurrent creates by the same owner that differ only in case (`Alpha`, `alpha`) can both pass the check and both be saved. | Making the index case-insensitive changes the schema and the behaviour (a migration; campaign rule: no new product behaviour), and the window is two simultaneous requests by the same user; documented, not fixed (F40 review, cycle 1). | `Reflekt.Persistence/Repositories/TeamRepository.cs`, `EntityConfigurations/TeamConfiguration.cs`; `Features/Teams/CreateTeam/CreateTeamEndpoint.cs` |
| **Architecture doc departs from the `create-architecture-doc` template.** It is `docs/architecture/architecture.md` (not `docs/architecture/{version}.md`), its sections follow the system as built (not the template's list), and its skill inventory adds two dispositions beside Referenced: "Not used by this app" and "Workflow". | The template forbids the as-built detail the doc exists for; skills are not edited (F40 spec, Decisions row 4). The skill still governs the inventory and the reference-don't-restate rule. | `docs/architecture/architecture.md`; `.claude/skills/create-architecture-doc/` |
| **White-flash prevention: `<style>` in `<head>`, not an inline body colour.** `tailwind-theme` § White Flash Prevention prescribes an inline `style` with a literal hex on `<body>`; `index.html` instead sets the `html` and `html.light` backgrounds in a `<style>` block in `<head>`. | An inline body colour beats the stylesheet, so the light theme kept a dark body (FE-05, fixed by F36). | `web/reflekt-web/index.html`; `docs/conventions/vue.md` § White Flash Prevention |
